## 修复内容

1. 增加统一媒体读取层。初始化用 FFprobe 和头尾小帧解码检查输入，损坏文件、纯音频、空文件和不支持的元数据给出可操作错误。特征、样本、人物扫描、匹配和渲染共用视频显示坐标与 PTS 定位。
2. 修复 VFR 与音轨起点偏移。WebM 的 Opus 预留时间可能早于视频；按容器起点剪切曾让一个短音轨组合提前两帧。现在以首个视频画面为时间零点，使用绝对时间定位，保留帧 PTS 再重采样。
3. 渲染保留源名义有理帧率。音轨统一 48kHz 双声道并补齐静音；无音轨保持无音轨。版本按累计时长分配整帧，避免每段单独取整后累积漂移，成片音频只合并重编码一次。
4. 增加检测内容缓存。键包含视频、参数、代码、FFmpeg 版本、模型和 BHE 源码哈希。命中跳过检测并恢复原始 JSON，损坏内容拒绝使用。命中状态放在单独运行记录，不污染可复现项目。
5. 增加明确的固定测试时钟和规范 JSON 排序。初测发现冷／热缓存的 JSON 对象顺序不同，虽然字段相同仍未满足字节一致；现在固定测试模式规范排序。它限制为 test_operator，不能伪装用户确认时间；普通项目继续记录实际审计时间。
6. 控制下游资源。FFmpeg 解码用两个线程，编码用六个线程，渲染滤镜用两个线程，OpenCV 用一个线程；motion 覆盖检测改成逐帧流式处理。源哈希按文件身份、大小及修改时间在单进程内复用。粗剪有哈希、时段和帧配额一致时直接用于版本，减少重复编码。
7. 人物扫描改用实际视频时长，避免用 VFR 的帧数除以帧率截短范围。人物通路的哈希原先一次读完整视频，已改为分块读取，消除了长文件引起的整文件内存分配。
8. 修复测试素材本身的缺陷。FFmpeg 8 的旧 rotate metadata 命令没有生成真实旋转；新增 display matrix 与显示尺寸断言并修正生成命令。低码率时间码损坏改为独立加测量条。没有删改或放宽旧测试断言。

## 性能前后对比

本机为 **Apple M1 Pro，10 核，16GiB 内存**。Python 为原生 arm64，FFmpeg 8.0.1 为 x86_64，通过 Rosetta 运行；编码使用 CPU libx264。实际环境为 Python 3.11.16、NumPy 2.4.6、OpenCV 5.0.0.93、psutil 7.2.2。软件版本、脚本哈希和采样数据均保存在 [性能结果](goal-2-performance.json)。

正式基准对每个步骤启动独立 CLI，包含各命令重新计算源哈希的成本。输入为 **60 分钟 1080p/30fps、带音轨、6,692,911,233 字节**的 CC0 派生文件；共 120 个六秒候选，输出全部 **720 秒粗剪**，最后保留并渲染 **60 秒**。两版输出均为 720p/30fps、CRF 22；旧版使用 fast，新版使用 veryfast。旧版导入预先存在的同一批候选，新版实际命中候选缓存，都不包含推理耗时。

| 完整 CLI 流程耗时 | 304.952 秒 | **246.249 秒** |
| 进程树采样 RSS 峰值 | 483.5 MiB | **275.5 MiB** |

新版耗时减少 **19.2%**，约为旧版的 **1.24 倍速度**。当前 **246.2 秒 < 300 秒**，**275.5 MiB < 2GiB**，两个门槛均通过。

总耗时还包含进程启动、表外读取项目／源哈希以及采样开销，因此不等于各阶段之和。准确的 FFmpeg 帧定位使特征提取更慢；编码并行和校验后的粗剪复用抵消了这部分成本。没有通过减少候选、缩短粗剪、降低源分辨率或放宽门槛来达标。

首轮同进程 API 测量曾得到 **302.287 秒**，超过五分钟限制，已按失败保存在 [首轮结果](goal-2-performance-first.json)。随后比较了编码并行参数，将编码线程从 2 调到 6、渲染滤镜从 1 调到 2，画质参数和帧率保持不变。调整后重新跑完全部 65 项矩阵和 61 项人物输入检查，再使用成本更完整的独立 CLI 基准复测。

内存值是主进程及其子进程 RSS 的采样总和，每次采样后等待 20ms，实际平均观察周期约 33ms。它包含本任务的 Python 和 FFmpeg，不含其他应用或系统文件缓存；无法测量权限不足时脚本会报错，不会以漏测数据宣称通过。

该门槛对应上面的明确工作量。素材由四秒片段重复生成，关键帧间隔约一秒；任意候选数量、保留时长、长 GOP 或一小时 4K 输入需要另外测量。基准走 features --no-ocr，不包含整场 YOLOX 推理。


## 回归与复现

原有 25 项行为测试、50 项评测测试和新增 17 项回归测试共 **92 项**全部执行通过，主测试环境中没有跳过。发布校验通过，覆盖 1,535 个发布文件。保护检查与实现哈希见 [校验结果](goal-2-validation.json)。另用不带视觉依赖的系统 Python 验证基础路径，8 项需要外部视觉依赖的原有测试按其原逻辑跳过；该结果单列，不把跳过算成完整通过。

新增 17 项回归覆盖媒体错误、真实旋转、VFR／音频预留时间、正数视频时间起点、缓存跳过外部 BHE 脚本、参数与清单变更、损坏缓存、哈希内容变动、分块读取、人物坐标、累计帧分配和固定时钟身份限制。原 Indiana 项目成功重放，并生成两个明确的测试剪辑版本；确认均为 test_operator。HTML 决策表单检查使用 Node.js 24，通过旧有断言；系统 Node 16 缺少 Blob，不适合运行这个检查。

完整命令见 [robustness/README.md](../../robustness/README.md)。本机测试复用了已存在的 BHE Python，包含视觉依赖；可在仓库根目录运行：
