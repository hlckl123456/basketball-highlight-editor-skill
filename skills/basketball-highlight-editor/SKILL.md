# Personal basketball highlights

Use `scripts/highlight.py` to create a resumable project. All script processing is local; no network calls, automatic package installs, video uploads, GUI internals or private project formats. BHE detection and people identification are separate tasks. A candidate is not a confirmed basket; a visible player is not necessarily the shooter.

## Workflow

1. **Receive the local video.** Inspect existing dependencies with `doctor`. Record its processing rights and source in a rights JSON, then `init`. Reuse an installed BHE runtime or an existing read-only DMG. Explain and obtain any necessary authorization before new downloads, software installation or external uploads. Do not install BHE just to use this skill.
2. **Find candidate plays first.** Use the public BHE source CLI through `detect --backend bhe`; supply the runtime directory, validate hoop ROI and retain raw detections, commands, logs and source/model hashes. Read [runtime details](references/runtime.md) for the tested interface. On failure, report the error. `motion-coverage` is an explicit low-specificity fallback that covers the video with overlapping windows; label those as review windows, never detected baskets. `import-candidates` accepts portable time ranges from user-exported BHE clips or another local detector. `add` repairs missed ranges. Avoid claiming complete recall from a scoring-only detector.
3. **Summarize visual evidence before asking who to edit.** For unnumbered footage, prefer `people` under an existing Python with OpenCV, NumPy and ONNX Runtime. The bundled official YOLOX-Nano model proposes real person boxes and clothing descriptors; inspect original frames and saved person previews before choosing samples. Use `features` for the older color-region/OCR evidence path; use `--no-ocr` when the players have no numbers. It saves sampled full frames, proposed clothing crops, color statistics and optional unverified OCR hints. HOG is used if present; otherwise color regions include non-people. Open `review.html`, inspect the original frames, and offer visual player cards. Report unknown numbers as unknown. Person detection alone does not establish a person’s identity. Codex visual review, if used, must be recorded as `agent_visual_review`, not local model inference or human confirmation.
4. **Ask which player.** Show reference images and ask the user to choose a visual card or point to a person. Do not assume jerseys have numbers. For an unnumbered player, first ask the user to confirm a full-body sample; use `sample` to save its timestamp, bounding box, clothing description and the actual confirmation reference. Prefer two clear views when teammates dress similarly. Compare shirt sleeves, shorts, shoes/socks and other stable clothing, with short-range continuity evidence. Saved sample optical flow is only a proposal, capped at two seconds in either direction. After saving samples, run `match-people --player ID --role scorer` (the default role) to inspect calibrated clothing and mutual-nearest short-track proposals; it performs no OCR or face embedding. `--apply` explicitly writes model proposals and invalidates prior confirmation. For `--role visible`, a high group means quality-gated clothing presence supported by one continuous track and actual competing-person/profile margins. For scorer/handler, clothing alone stays uncertain; only explicit reviewed role evidence can promote it. No group is an identity probability. Similar clothing can still produce false matches. Neither flow nor clothing tracks can safely bridge arbitrary occlusion, camera cuts or lookalikes. If evidence is insufficient, keep the candidate uncertain and request a better sample. Do not use faces, body size, team color alone or an invented confidence percentage as an identity substitute.
5. **Make the rough selection.** Review `people/candidate-proposals.json` and `people/matches.json`. `match-people --apply` records profiles and candidate proposals as `local_model`, requiring at least three accepted observations over 0.5 seconds on one continuous track, quality/region agreement and no known ambiguity for a high visible-presence assignment; insufficient evidence stays uncertain. It never marks a no-match clip or another person’s presence as proof that the target is absent. Use `select --role scorer|handler|visible`; automatic matching defaults to scorer and persists that scope. Legacy manual selection defaults to visible for compatibility, explicitly labelled in HTML/CSV. Automatic reference expansion is saved separately as draft and never joins confirmed samples. See [attribution rules](references/attribution.md). For manually reviewed profiles and assignments use `annotate`, then `select` using the user’s actual answer. High confidence requires a visible verified number or a saved confirmed sample match, with timestamps and a reason. A color match alone cannot enter that group. Record `role` such as shooter, ball handler, off-ball defense or merely visible; do not label someone’s presence as their made basket. Use `needs_review` for overlap, uncertain role or editorial questions even when identity is clear. Run `rough` to produce separate high-confidence and uncertain clips plus CSV and HTML. Keep excluded items and raw evidence recoverable. “All” means all supported matches among these candidates, not every possible involvement in the source recording.
6. **Have the user review the clips.** They may reply with keep/reject IDs or use the local HTML form to download a decision JSON. Include all high-confidence and uncertain IDs. Read the current revision before applying decisions; stale or incomplete review is rejected. Never invent a human reply. Tests must use `reviewer_kind: test_operator`, clearly distinguished from `user`.
7. **Stop after confirmation.** `confirm` writes `confirmed-edl.json` and enters `awaiting_edit_prompt`. Preserve the project, source reference, evidence and rough media. Do not call `version --render` in the same action merely because selection was confirmed. Tell the user the project is ready and wait for their next editing prompt.
8. **Make versions only on a later prompt.** Translate that prompt into an explicit version spec (clip order, selected IDs, duration cap and prompt text), then `version`. Render only if requested. New versions draw from the same confirmed master and cannot reintroduce rejected candidates. The tested renderer supports clean landscape cuts and duration caps. Music, subtitles, smart reframing, slow motion and editable CapCut/Jianying projects require a separate verified workflow; do not claim they are implemented here.

## Commands and project state

Read [commands and schemas](references/workflow.md) when operating the CLI. `project.json` is authoritative; `candidates.csv` and `review.html` are review surfaces, and `confirmed-edl.json` is the portable cut list. Keep the original video available and unchanged; every mutation checks its SHA256. A new selection, annotation, sample or candidate invalidates confirmation. Tests: `python3 -m unittest discover -s <skill>/tests -v`.

For measured results and the deliberately small public test corpus, read [validation and limits](references/validation.md). The archived earlier matcher on two unnumbered target scenes passed the documented short-clip gate on randomized time-point holdouts (36 correct, zero observed false identity assignments, five misses among 41 visible target frames). The similar-clothing stress scene failed the recall gate. These operator-derived historical measurements are not current human-confirmed scorer/handler accuracy. The current stricter policy has only one independent human-confirmed positive presence clip and no confirmed scorer/handler facts. Do not present test-operator confirmations as user approval, omit failures, or extrapolate these correlated short-clip samples to full-game reliability.

For VFR phone video, rotation metadata, short/missing audio, detection caching or repeatable tests, read [media handling](references/media.md). Frame extraction and rendering use presentation seconds from the first video picture; source files stay unchanged.
